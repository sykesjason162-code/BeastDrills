練習 ゲーム内 各ページ WongScript ドリルの作成

練習

Beast Drills はストリートファイターのための間隔反復（スペースド・リピティション）練習ツールです。 ドリルはそれぞれ、保存されたトレーニングモードの設定と「何ができたら成功か」というルールの組み合わせです。 予定の来たドリルを練習すると、アプリが実際に起きたことを見て判定し、 失敗が続くドリルほど早くまた出てきます。

セッションの流れ 0.1.0 · 更新 0.2.1

  1. メニューバーから開始します（ドリル → セッション開始、 またはテンキー2）。いちばん期限を過ぎているドリルが選ばれます。
  2. 最初にブリーフィングが表示されます。ドリルの内容、設定、 何ができたら成功かが書かれています。「ドリル開始」で始まり、「キャンセル」で戻ります。 内容を覚えているなら、設定 → ブリーフィングを表示 でオフにできます。
  3. トレーニングモードの設定はアプリがまとめて適用します — ダミーの動作、 レコーディング、リバーサル、ガード、カウンター設定、立ち位置。ドリルに書かれて いない設定は前の状態を引き継がずにリセットされるので、前のドリルの設定が 残ることはありません。
  4. レップ（1回の試行）を繰り返します。セッション中はパネルが邪魔にならないよう引っ込みます。
  5. 規定回数が終わるとドリル完了のポップアップに、何回成功したかと評価が表示され、 次のドリル、もう一度やる、完了を選べます。
  6. 終わるとトレーニングモードが元に戻ります。リプレイ停止、ダミーは立ち状態、 両者は中央へ。同じ設定のまま手動で練習を続けたいなら、設定 → 終了時に位置をリセット をオフにしてください。

評価とスケジュール 0.1.0

セッションは Anki と同じく4段階のどれかで評価されます：もう一度、 難しい、普通、簡単。評価が良いほど次の 復習は先に延び、「もう一度」なら翌日に戻ってきて連続成功がリセットされます。評価を自分で 選ぶことはありません — アプリが観測した結果で決まります。

練習するドリルの選び方 0.1.0 · 更新 0.2.0

すべてのドリルにはチェックボックスがあります（ゲーム内とドリルページの両方）。 分かりにくいので、ルールを覚えておく価値があります：

  • 何もチェックしていない — 予定の来たドリルがすべて対象になります。
  • どれかをチェックしている — チェックしたものだけが出ます。

ゲーム内の一覧の上に、今どちらの状態かが表示されます。

新しくインストールするとスターター用の10個のドリルにチェックが入った状態で 始まるので、最初のセッションからいきなりライブラリ全体が出てくることはありません。 予定の来たドリルを全部やりたいならチェックをすべて外してください。ただし、何もチェックが ない状態で新しいドリルを追加するアップデートが来ると、スターターに再びチェックが入ります。 何かチェックが入っていれば、アップデートはその選択に手を触れません。

難易度 0.1.0

ドリルには難易度をつけられます — very-easy、 easy、medium、hard、 very-hard — 自動で選ぶときはこれが使われます。初日から 1フレームも許されない画面端ルートを渡されても意味がないからです。

  • 簡単な2段階は最初から開いています。
  • 次の段階は、ひとつ下の段階のドリル2つが連続成功2に 達すると開きます。新しいスコアを稼がせるのではなく、スケジュールが既に持っている 連続成功をそのまま使います。
  • 段階は順番に開くので、hard を1つまぐれで通しても very-hard は 開きません。
  • 難易度のないドリルには制限がかかりません。「不明」は「難しい」と 同じではないからです。

これはアプリが代わりに選ぶときだけの話です。自分でドリルを選べば いつでも練習できます — わざわざ取りに行く人から隠すものは何もありません。

ドリルを探す 0.1.0

ライブラリは大きく — SuperCombo からの取り込みで2,000を超えています — そのためドリルページには単なる絞り込みではなく本格的な検索ボックスがあります。画面に 見えているものだけでなく全体を検索します。複数の語はAND条件で、すべてを満たすものが出ます。

検索の対象はドリルの英語の名前とIDです。 キャラクターも英語名で入力してください（リュウなら ryu、JP なら jp、 不知火舞なら mai）。コンボは 2MK のような英語表記で書かれています （弱P = LP、中P = MP、強P = HP、弱K = LK、中K = MK、強K = HK）。

対戦記録 0.1.2

実際の対戦 — アーケード、対戦、ランクマッチ、カジュアルマッチ、バトルハブ、 ルームマッチ — はすべて裏で記録され、対戦記録ページで ラウンドごとに、勝ち負けではなく集計（何を当て、何を食らったか）にもとづいて評価されます。記録はゲームを 読むだけです：何も変更せず、対戦中にゲーム内に何も表示しません。ドリルは trains: で何を鍛えるかを宣言でき、最新の対戦でいちばん悪かった点を鍛える ドリルが次のセッションで先に出ます — 予定の来たドリルの中での並べ替えで、 それらの代わりになることはありません。

全対戦の通算成績はずっと残ります。個々の対戦は 50 MB を超えると古いものから 削除されます（beast_drills.ini の [matches] max_size_mb、 0 で無制限）。対戦記録ページで対戦にスターを付けると、その対戦は ずっと残ります。

帯（ベルト） 0.2.0

プロフィールページには、使っているキャラクターごとに白から黒までの帯が 表示されます。そのキャラクターの帯ドリルの成績から決まります。帯を取るには、 その帯のスキルをすべて合格する必要があります：そのスキルのドリルを少なくとも3つ （3つ未満なら全部）70%以上で。帯ドリルもほかのドリルと同じようにスケジュールされ、 練習できます。違いは帯に数えられることと、開発者用インストール以外では誤って 変更されないよう読み取り専用になっていることだけです。

練習モード 0.2.1

ドリル → 練習は、ドリルとまったく同じ設定にゲームを 整えます — ダミー、そのレコーディングとリバーサル、ガード、立ち位置、 ゲームスピード — そしてそのあとは何もしません。10回で止まることも、最後に 手応えはどうだったかを聞かれることもなく、スケジュールにも 統計にも何も残りません。練習しても復習したことにはならないので、 次の予定日と連続成功はそのままです。

選択しているドリルを練習します。何も選んでいなければ次に予定の来ているドリルです。 バーには練習、ドリル名、成功したレップ数が表示されます。コンボドリルでは コンボ手順がこれまでどおり各ステップを点灯させ、SUCCESS を表示します。 止めるには同じメニューの練習を終了かテンキー2。 トレーニングモードの設定はセッションのあとと同じく元に戻ります。

お気に入り 0.1.0

ドリルカードのスターでお気に入りになります。お気に入りは ドリルページの先頭に並びます — 今見ているページだけでなく ライブラリ全体で — 検索では favorite:yes で見つかります。

お気に入りだけで練習することもできます：お気に入りで セッションを始めると、スターを付けたドリルだけが出ます。ただし予定が来ている必要があります — お気に入りは候補の絞り込みであって、スケジュールを飛ばす方法ではありません。

これは選択（チェック）とは別のもので、どちらかが置き換わるのではなく 組み合わせて使います：

意味
選択今練習の対象にしているもの。何も選ばなければ全部が対象です。
お気に入り自分で作る長く使う候補リスト。お気に入りのセッションをわざわざ始めたときだけ対象を絞ります。

キャラクター指定のないドリル 0.1.0

ほとんどのドリルはキャラクターが決まっています。決まっていないものもあります — 対空、パリィ、ヒット確認、投げ抜け。これらは基礎で、 使うキャラクターごとに別々にスケジュールされます。

JP で対空ができても、リュウで対空ができるかは分かりません。だから片方を練習しても もう片方は済んだことになりません。今使っているキャラクターでまだ練習したことのない基礎は 新規扱いで、すぐに出てきます — ほかのキャラクターでどれだけできていてもです。

ドリルページも同じ考え方です：ゲームの起動中は、表示されている状態が実際に 読み込まれているキャラクターのものになります。ゲームを閉じていると対象のキャラクターが いないので、全キャラクターをまとめた表示になります。

ドリルの出どころ 0.1.0

ライブラリの大部分は、英語圏の格闘ゲームwiki SuperCombo wiki から取り込んだものです： 全30キャラクターでおよそ2,000のコンボで、各コンボの位置、ダメージ、難易度、メモも 一緒に取り込んでいます。全キャラクターのフレームデータも合わせて取り込んでいます。

取り込んだドリルはわざとチェックなしで入ります。自分で何かを 加えるまでは、あなたの選んだものが練習の中心のままです — 見知らぬ2,000個に 練習を乗っ取られるべきではありません。

wiki のコンボのすべてを正確に変換できたわけではありません。アプリが正確に表せない 表記のコンボは、近いもので代用せず取り込みを見送っています：少しずれた成功 ルールはずっと「もう一度」と評価され続け、検出の故障とまったく見分けがつかないからです。

ドリルが採点できないとき 0.1.0 · 更新 0.2.1

セッション中、ドリルメニューに次の3つの警告が出ることがあり、どれもあなたの失敗では ありません：

  • 「成功条件がありません。このドリルは採点できません」 — 何をもって成功とするか のルールがドリルにないので、どうプレイしても毎回「もう一度」になります。ドリルページで 直してください。
  • 「このダミーのレコーディングスロットが空です」 — ドリルが指定しているレコーディングスロットに、今の相手キャラクターの 記録がないので、ダミーは立っているだけになります。レコーディングはキャラクターごとです。
  • 「採点できない成功条件：…」 — ドリルが、採点の 仕方を誰も知らない成功カテゴリーを求めています。成功条件がないのと同じ結果ですが、原因は 空欄ではなく名前です。

WongScript

WongScript（.wong）は、ドリルを1行に1つの設定で書くテキスト形式です。 ドリル作成フォームで保存したものとまったく同じ内容になります — フォームの代わりではなく、 もうひとつの編集方法です。書いた行だけが初期値を上書きし、書かなかった項目は設定されません。

ボタンの書き方について：WongScript はボタンを英語の略号で書きます。 LP = 弱P、MP = 中P、HP = 強P、LK = 弱K、MK = 中K、HK = 強K、 PP / KK = OD、HPHK = ドライブインパクト、 MPMK = ドライブパリィ。方向はおなじみのテンキー表記です （236 = 波動拳コマンド、623 = 昇竜拳コマンド、214 = 竜巻コマンド、2 = しゃがみ）。 つまり「しゃがみ中K > 波動拳（中P）」は 2MK, 236MP と書きます。

ダミーの動きを決める2つの方法 0.1.0

SF6にはダミーを動かす仕組みが2つあり、WongScript ではそれぞれ書き方が違います：

  • リバーサル設定 — ダミーの通常技・必殺技・SA・共通アクション （前歩き、バックステップ、投げなど）からメニューで選ぶ方式です。WongScript ではスロットの下の action: 行がそのまま「ダミーが出すもの」になります（type= ＋ skill= ＋ 遅らせるフレーム数）。上の例はこの方式です。SF6のリバーサル設定は 出すタイミングの違う3つのタブ（各10スロット）に分かれていて、 WongScript にもそれぞれのキーがあります：
    • wake-up-rev-slot: — ダミーがダウンから起き上がるときに出します（起き上がりリバーサル）。
    • block-rev-slot: — ダミーが攻撃をガードした直後に出します（ガード後のリバサ・暴れ）。
    • damage-rev-slot: — ダミーが攻撃を食らった直後に出します。
    ドリルで使うのは、練習したい場面に合う1つだけでかまいません。ほとんどのドリルは1つです。
  • レコーディングスロット（rec-slot:）— 自由な入力を 記録したもので、リバーサルのメニューにない動き（連携、重ね、仕込みなど）も再現できます。 リバーサル設定とはまったく別の仕組みです。中身を入れる方法は2つあります：トレモで ダミーの動きを手で記録してから現在の設定をドリルとして保存（ゲーム内か ダッシュボード）で記録をドリル自体に取り込む方法 — 以後はドリルを始めるたびに 記録がスロットに書き込まれて再生されるので、トレモ側のスロットの中身に左右されません。 もうひとつは WongScript の action: に直接書く方法です（リバーサルと同じ キーワードですが、こちらでは内蔵の技ではなく実際のコマンド表記を書きます。次の節を 参照）。単純な入力ならトレモでの記録は要りません。rec-slot: 行はそのスロット （と、どちらかの方法で入れた中身）を有効にするだけです。トレモの記録も、取り込んだ記録も、 action: 行もないスロットを指定すると、黙って何もしないのではなく 「スロットが空です」と警告が出ます。さらにドリルごとに、SF6のリプレイ設定画面と同じ 2つを設定できます：weight:（ランダム選択の比率 — 複数のスロットが 有効なとき、値が大きいほどそのスロットがよく選ばれます）と、ドリル全体の repeat-replay:（リピート再生：オフ／オン／常に）です。

迷ったら：メニューから選べる技で済むならリバーサル設定、 連携や細かいタイミングが要るならレコーディングスロットです。実際のドリルは、最初は レコーディングが要りそうに見えても、リバーサル設定で済むことがほとんどでした。

title: Example Recorded Meaty
position: player-corner-left
reps: 10
repeat-replay: always

rec-slot: 0
action: 236HP, [6:10f], 22LK, [4:4f]
weight: 1
success: perfect-parry

（強P波動拳のあと前に10フレーム歩き、22弱K、後ろに4フレーム — これにジャスパで返せたら成功、という重ねの練習です。）action: 行を省いた スロットは、トレモで記録済みか、以前の取り込みでドリルに記録が入っている必要があります — rec-slot: と weight: だけでは中身は作られません。 中身を作るのは action: だけです。

レコーディングの入力の書き方 0.1.0

レコーディングスロットでダミーが実際に入力する内容です。コンボ表記と同じ書き方 （236P、623P）で書けますが、1つだけ追加があります：長く押し続ける 入力（特に溜め）のために、フレーム数を明示する括弧の書き方です。普通のコンボ表記は フレーム数を書きませんが、ダミーに入力させるには必要だからです。

  • 通常の入力 — 方向（テンキーの1〜9、ニュートラルは 5 か N）かボタン（LP/MP/HP/ LK/MK/HK）で、それぞれ2フレーム押します — 236HP のような普通のコマンド入力と同じ速さです。区切らずに続けて 書くとコマンドになります：236HP は 下、右下、そして 右＋強P を同時に。 （コマンドの最後の方向は直後のボタンと必ず同時押しになるので + は要りません — 実際のプレイヤーも最後の方向とボタンは同時に入れます。手前の方向、ここでは 2 と 3 はそれぞれ別の入力のままです。）数字なしのボタンだけ （例：HP）はニュートラルでのボタン押しです。
  • 押し続ける入力 — [<入力>:<n>f]。 例：[6:10f]（前に10フレーム）、[2:5f]（下に5フレーム、溜めの場合）。 溜め技も上の同時押しのルールと組み合わせるだけです：[2:5f]8HK は 下に5フレーム溜めてから、上＋強Kを同時に押して離します。
  • 同時押し — どちらの書き方でも + でつなぎます： HP+HK（ドライブインパクト、すばやく同時押し）、[6+HP:8f] （前＋強Pを8フレーム押し続ける）。ボタンを2つ以上続けて書く（HPHK）のも同時押し です — HP+HK と同じ意味で、インパクトやラッシュを短く書けます。 方向のすぐ後ろのボタンも常に同時押しになります（上の「通常の入力」）。方向とボタンを本当に 別々に押したいときは、どちらかを括弧で押し続ける形にします。例： [6:2f]HP。
  • ステップと切り返し — 同じ方向を2回（または真逆の方向を） 続けて書くと、間に見えない「離し」が自動で入り、1回の長押しではなく2回の入力として 認識されます：66（前ステップ）、44（バックステップ）、 46、28、斜めの逆方向も同じです。括弧で書いても同じで、 [6:2f][6:2f] にも 66 と同じ離しが入ります。ドライブラッシュにも 特別な書き方は要りません：生ラッシュはコンボの最初に 66MPMK、 キャンセルラッシュはコンボの途中に MPMK だけです。例外はなく、溜めの解放も 同じなので [2:45f]8HK は「下に45フレーム、ニュートラル、上＋強K同時」と読みます。

カンマは見やすさのためだけでなく、本当の区切りです。 カンマで区切った2つがどちらも技なら、その間に約0.1秒のニュートラルが自動で入ります。 理由は実際に起きた不具合です：前歩きの押し続けから区切らずに波動拳コマンドを書いた （[6:20f]236HP、カンマなし）ところ、ダミーがまったく別の必殺技を出しました。 SF6の入力判定は直前の入力の流れ全体を見るので、押し続けの最後とコマンドの最初が偶然 別のコマンドになっていたのです。カンマで区切る（[6:20f], 236HP）と、 見えないニュートラルが間に入り、それぞれのコマンドがきれいに認識されます。この間は自動で、 テキストには表示されません。例外が2つあります：1つの入力の中（236HP の各方向）には 入りません。また、自分で書いたニュートラル（[N:12f]、N など）の隣にも 入りません — 自分で書いた間が同じ役目を果たすので、重ねて入れません。自分で書いた ニュートラルは表示し直しても消えず、カンマも残ります：4, N, 6HP, N, 2, N, 8HK は いつでもそのまま表示されます。既存のドリルの記録を WongScript で開くと、各入力が実際の フレーム数つきの括弧の形で表示されます。トレモで記録した入力のタイミングは2フレームの初期値と 一致しないことが多いからで、手で書いたものより長くなりますが、内容は正確です。

順番のある成功条件 0.1.0

カンマはどれか1つ、> はこれをして、それから次 — レップを成功にするために必要な順番です。

success: block > hit          ガードしてから当てる
success: hit > combo          当ててから追撃が続く
success: block > hit > combo  段数はいくつでも
success: hit > combo, block > hit    どちらの流れでも成功

順番はあとから推測するのではありません。レップ中にそれぞれが最初に起きた瞬間を 記録しているので、block > hit は本当にガードが先だったことを意味します — 当ててからガードしたレップは確反ではなく、失敗として採点されます。

つなげられるのは次のものです（自分から見た名前）：

自分がしたこと：hit（当てた）、combo（コンボ）、 attack（攻撃を出した）、block（ガード）、parry（パリィ）、 perfect-parry（ジャスパ）、throw（投げ）、 throw-tech（投げ抜け）、counter-hit（カウンター）、 punish-counter（パニカン。punish-counter-hit とも書けます）、 anti-air（対空）、reversal（リバサ）、backroll（後ろ受け身）、 wakeup（起き上がり）、drive-impact、drive-impact-counter、 drive-impact-vs-di、stuff-dash、stuff-drive-rush。
相手にされたこと：got-hit（食らった）、 got-blocked（ガードされた）、got-thrown（投げられた）、 got-counter-hit（カウンターを食らった）、got-punish-countered（パニカンを食らった）、 got-drive-impacted（インパクトを食らった）、got-anti-aired（対空された）。

上の表の条件は do-nothing 以外すべてこの形でつなげられます。 do-nothing が使えないのには理由があります：順番は「いつ起きたか」を見るので、 何も起きないことには瞬間がないのです。

つなげられないのは技です。punish-counter-hit > DR > ... は 自然に読めますが、意味が違います — ここに書くのは結果（誰に何が起きたか）であって、 押したボタンではありません。どの技を出したかは、combo: 欄のコンボ表記で判定します。

上の表の名前のいくつかは、これらの流れの短縮形で、どちらで書いても同じです — 読みやすいほうを使ってください：

hit-confirm        =  hit > combo
pressure           =  got-blocked > hit
block-then-punish  =  block > hit

テスト用ドリル 0.1.0

IDが debug_ で始まるドリルはテスト用ドリルです： 何かを教えるためではなく、検出の仕組みを試すためのものです。debug_ ○○ と 名前をつけるとテスト用になります。ドリル検索で debug_ と入力すると見つかります。

普通のドリルとの違いは2つだけで、どちらも意図したものです。自動では出てきません — セッションに入ることも連続成功に数えることもありません — そして 配布されませんので、他人のテスト用の仕掛けがインストールされることはありません。 自分で選べば普通に動きます。そのためのものです。

決めるのは名前ではなくIDで、これも意図どおりです：IDはドリルを作ったときに一度 決まり、編集では変わらないので、テスト用ドリルを名前の変更で本物にして、スケジュールされたり 配布されたりすることはありません。説明には、何を見ればよいかと、失敗したらどう見えるか を書いてください。テスト用ドリルがあるのは、確かめたいことがコードを読むだけでは 確認できないからです。

技の指定 —「type」と「skill」 0.1.0

起き上がりリバーサルの選択肢はどれも5つの種類（type=）のどれかに属し、 その種類の一覧の何番目かが skill= です。どちらもゲーム自体の内部データと、 実際のゲーム内のリバーサル設定のメニューで確認したもので、推測ではありません。

  • type=common — 全キャラクター共通の一覧：do-nothing（何もしない）、forward（前歩き）、backward（後ろ歩き）、forward-dash（前ステップ）、back-dash（バックステップ）、vertical-jump（垂直ジャンプ）、forward-jump（前ジャンプ）、backward-jump（後ろジャンプ）、normal-throw（通常投げ）、drive-parry（ドライブパリィ）、drive-impact（ドライブインパクト）。
  • type=normal（通常技）、type=command-normal（特殊技）、type=special（必殺技）、type=sa（SA）— これらはキャラクターごとです（normal も、考え方は全員同じ12個の通常技ですが、一覧はキャラクターごとに保存されています）。そのキャラクターの技一覧を取得済みのときだけ技名で書けます（今のところ取得済みはリュウだけです）。使うときは dummy: に相手のキャラクターを書いてください。技名が分からないときは、WongScript は推測せず、どの行が問題かを教えてくれます。

まだ一覧を取得していないキャラクターでも、番号で直接書けます — action: type=special skill=2, 0f — 一覧が取得できたらあとで直せばよいのです。 ダッシュボードのフォームのタブも同じです：スロットの「ダミーの行動」で種類を選ぶと、 取得済みのキャラクターを dummy: に選んでいれば技名のドロップダウンになり、 そうでなければ（未取得のキャラクターでも）番号の入力欄になります。

＋新規ドリル（既存のドリルなら編集）を押すと編集画面が 開きます。タブが2つあり、どちらで保存しても同じものになります：

  3. フォームに入力欄のないものを書き足します — 順番のある success: block > hit、レコーディングの action:、 combo: のコンボ表記など。
  4. 保存を押します。

タブを切り替えると、作業内容はどちら向きにも引き継がれます。内容はページの中にあるだけで、 保存を押すまで何も書き込まれず、何度行き来しても キャンセルですべて破棄されます。

フォームに戻っても、手で書いたスクリプトの書き方は崩れません。テキストがフォームから 作り直されるのはフォームで実際に何かを変えたときだけなので、フォームを見てから戻っても、 自分で入れた空白や書き方はそのままです。

フォームは入り口、WongScript は細かい設定の置き場です。どちらが「本物」ということはなく、 どちらかを選ぶ必要もありません — 同じドリルを2つの形で見ているだけです。

項目に実際の動作をさせる

登録しただけで手に入るのはメニュー項目、ホットキー、設定です。動作は付きません： クリックは mods/_events/ にファイルが書かれるだけです。そのフォルダーを自分で見張るか、 項目が何を動かすかを教えてくれれば、こちらで動かします。

キー動作
call 項目がクリックされたときに呼ぶ Lua のグローバル（ドット区切り："MyMod.scan"）。 関数なら項目の args で呼び、真偽値なら切り替えます（メニュー項目がフラグに 対して意味するのはそれです）。パスはグローバル表をたどるだけで実行はしないので、名前を書いても すでにある値にしか届きません。
checkbox あなたのMODがすでに描いているチェックボックスの文字列。Beast Drills は imgui.checkbox を通るのを見ているので、メニューのチェックはあなたの本当の状態で、 クリックするとその本当の状態が変わります。あなたのコードは何も変わりません。
from プレイヤーがあなたの画面を開く前にその値を知るため、画面外で一度だけ実行するスクリプトファイル。 なければ、最初に描かれるまで項目は正直に（まだ見ていません）と表示します。
window このトグルが開くウィンドウ。その閉じるボタンでトグルがオフになります — 設定する価値があります。 begin_window(title, true, 0) を呼んで結果を捨てるMODの×ボタンは動かないからです。
draw 分かりやすいメニュー項目のないMOD向けに、画面全体を Beast Drills のパネルの中に表示します。 登録している間は2か所ではなく1か所に描かれます — 複製ではなく移動です。
toggle 0.2.0 Lua ではないMOD（REFramework.NET のプラグイン）用のチェックボックス。checkbox は Lua の imgui.checkbox を見る方式なので、C# のMODは toggle と書き、 自分の状態を mods/_toggles/<yourmod>.json に項目IDごとに書き出します （{"show": true}）。クリックはこれまでどおり mods/_events/ に届きます。 Beast Drills 自身のコンボ手順もこの方式で作られています。

ローカル変数には誰も届きません。状態がローカル変数にあり、表示文字列に頼りたくないなら、 外に出してください — 1行足すだけで、動作は変わらず、同じ表です：

local p1 = make_config()

MyMod = { p1 = p1 }        -- the only line you add
{ "id": "p1", "label": "P1 info", "call": "MyMod.p1.enabled" }

あなたの描画コードはこれまでどおりの項目を読むだけで、誰が設定したかを知ることはありません。 これが確実な方法で、checkbox はそうしていないMOD向けです。

対応していないバージョンのファイルは、中途半端に登録せず全体を拒否し、メニューにそう表示します。 読み取れないファイルも飛ばさずにエラーと一緒に一覧に出します — 末尾のカンマ1つで1時間 失うのを防ぐために、このページはあります。

frame_trap_finder = reframework/autorun/FrameTraps/beast.json

これで項目はあなたのMODと一緒に現れ、一緒に消え、私たちのフォルダーにあなたのものは何も残りません。 ほかはすべて同じです：同じ形式、同じイベント、同じホットキー。

パスはストリートファイター6のフォルダーからの相対パスなので、Steam ライブラリを別のドライブに 移しても使えます。そのフォルダーの外を指すパスは無視します — .ini は フォーラムの書き込みを貼り付けるかもしれないテキストファイルだからです。ファイルが見つからない パスは黙って飛ばします（アンインストールしたMODはそう見えるからです）。それ以外の誤りは mods/ のファイルと同じくメニューに表示します。すでに登録されている名前は2つ目を拒否して そう表示します。名前が同じだとイベントのファイル名も同じになり、片方のクリックをもう片方が 黙って受け取ってしまうからです。

設定はプレイヤーのファイルに

MODごとに設定ファイルを探させると、beast_drills.ini が解決した問題に逆戻りです。 同じ登録ファイルで設定を宣言すれば、プレイヤーのファイルに現れます：

"settings": [
  { "key": "gap_frames", "default": 3,
    "note": "How wide a gap counts as a frame trap." }
]

Beast Drills は登録名のセクションを追加し、あなたの説明をコメントとして書きます（自分の設定と同じ作り方です）。 ini を読む必要はありません — 解決済みの値が、すでに見張っているイベントの隣に mods/_settings/<yourmod>.json として届きます。私たちが管理する形式を読むパーサーが 2つあると、初期値について食い違うことがあり、その食い違いはあなたのMODの中で黙って起き、 あなたが私たちのファイルをデバッグすることになるからです。

そのファイルはプレイヤーのものなので、3つ約束します：プレイヤーが設定した値は決して変えません。 プレイヤーのコメントと並び順は残ります。MODをアンインストールしてもセクションは消えません — 1週間後に戻しても、設定はそのままです。

クリックは1つのファイルとして届きます：

mods/_events/frametrap_1787900000000.json

{ "mod": "frametrap", "item": "scan", "at": 1787900000 }

そのフォルダーを見張り、処理したらファイルを空にしてください。タイムスタンプはミリ秒で ゼロ埋めなので、普通に並べ替えれば時刻順になります。

pcall(fs.write, path, "")   -- consumed

削除しようとせず、空にしてください。REFramework は Lua から os.remove を外していて、 fs にあるのは glob、read、write だけなので、 Lua のMODはファイルを削除できません。os.remove は nil を呼び、pcall がそれを 握りつぶし、イベントはそのまま残って、見るたびに読み直され処理し直されます。そう作ったトグルは 1秒に何度も切り替わります。空のファイルは読み取れないので二重に処理されることはなく、Beast Drills が 空のファイルを片付け、1分より古いものも消すので、入っていないMODのクリックがたまり続けることもありません。

この間接的な仕組みは意図的です：クリックのときに動いていなかったMODも、起動すればそれを受け取れます。

MODはホットキーも登録できます。Beast Drills やほかのMODがすでに使っているキーは拒否し、理由を ショートカットの位置に表示するので、効かないキーが謎になることはありません。MOD同士ではアルファベット順で 先のものが使います — 恣意的ですが、読み込み順で入れ替わるより安定しています。 "Num9" も "Numpad9" も使え、読めない名前も無視せず同じように表示します。 ホットキーは Beast Drills の画面にフォーカスがあるときだけ効くので、MODのホットキーが対戦中に 漏れることはありません。

MODにできないこと 0.1.0

ゲーム画面の上に直接描くことはできません。それには ImGui の描画リストが要りますが、 ここのプラグインからそれを使うとSF6が落ちます — 2回試して2回ともゲームが落ちました。 MODはこれまでどおり REFramework を通して自分のウィンドウを描いてください。

ほかのMODのローカル変数には届きません。値がローカル変数にあり、どのグローバルも持っていなければ、 誰にも名前で指せません — 私たちにも、ほかのMODにも、デバッグライブラリにも。だから checkbox は文字列を見ているのです：変数に届かなくても、値は私たちが包める関数を通るからです。

内部への手出しもできません — セッションのオブジェクトもスケジューラーもありません。読む価値の あるものは上のファイルにすべてあり、そちらは内部と違って、アップデートをまたいで変わらないよう守っています。
